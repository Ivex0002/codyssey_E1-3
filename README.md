## 기능 요구 사항
### 1. 데이터 구조
- n×n 크기의 2차원 패턴 및 필터를 저장할 수 있어야 한다.
- 특정 위치의 값을 저장하고 읽어올 수 있어야 한다.
- 최소 3×3, 5×5, 13×13, 25×25 크기를 처리할 수 있어야 한다.

### 2. 모드 1 입력 처리(3×3)
- 3×3 필터 2개(A, B)를 “한 줄씩(공백 구분)” 입력받아 저장해야 한다.
- 3×3 패턴을 동일한 방식으로 입력받아 저장해야 한다.
- 입력 검증(최소 기준):
    - 행 수/열 수 불일치, 숫자 파싱 실패 시 안내 문구를 출력하고 재입력을 유도해야 한다.
    - 예: “입력 형식 오류: 각 줄에 3개의 숫자를 공백으로 구분해 입력하세요.”
 
### 3. 모드 2 JSON 로드 및 스키마 검증(data.json)

`data.json`

- data.json에서 아래 구조를 읽어올 수 있어야 한다:
    - filters: size_5, size_13, size_25
    - patterns: size_{N}_{idx} 형태의 키와 input(2차원 배열), expected 값 포함
- patterns의 각 항목에 대해, 키에서 N을 추출하여 해당 size_N 필터를 선택해야 한다.
- 필터와 패턴의 크기가 일치하는지 검증해야 한다.
    - 불일치 시, 해당 케이스를 FAIL로 처리하고 원인을 메시지로 남겨야 한다 (프로그램이 비정상 종료되면 안된다).

### 4. 라벨 정규화(표준화) 필수 구현
- 프로그램 내부에서 “표준 라벨” 2가지를 사용한다: Cross, X
- 아래 입력들을 표준 라벨로 정규화해야 한다:
    - expected 값: ‘+’ → Cross, ‘x’ → X
    - filter 키: ‘cross’ → Cross, ‘x’ → X
- 콘솔 출력 및 PASS/FAIL 비교는 표준 라벨(Cross/X)을 기준으로 수행해야 한다.

### 5. MAC 연산 (외부 라이브러리 금지)
- 입력 패턴과 필터를 위치별로 곱하고 모두 더하는 연산을 구현해야 한다.
- NumPy 등 외부 라이브러리 없이 반복문으로 직접 구현해야 한다.
- 연산 결과(점수, float 가능)를 반환해야 한다.

### 6. 점수 비교 정책(부동소수점/동점 처리 기준)
- 점수 비교는 “허용오차(epsilon) 기반” 정책을 적용해야 한다.
- 권장 기준(예시): abs(score_a - score_b) < 1e-9 이면 동점으로 간주한다.
1. 판정 및 PASS/FAIL 출력 규칙
- 두 필터 점수 비교 후 A 또는 B로 판정하거나(동점은 UNDECIDED), 결과를 출력한다.
- 각 패턴에 대해 Cross 필터 점수, X 필터 점수, 판정(Cross/X/UNDECIDED)을 출력한다.
- 판정(Cross/X)이 expected와 같으면 PASS, 다르면 FAIL을 출력한다.
2. 성능 분석(측정 기준 포함)
- 크기별 MAC 연산 시간을 ms 단위로 측정해야 한다.
- 최소 기준: 각 크기별로 MAC 연산을 10회 반복 측정 후 평균 시간을 출력한다.
- 시간 측정은 I/O(입력/출력/파일 읽기) 시간을 제외하고 “연산 함수 호출 구간” 중심으로 수행하는 것을 권장한다.
- 표에는 “크기(N×N) / 평균 시간(ms) / 연산 횟수(N²)”가 포함되어야 한다.
3. 결과 리포트(콘솔 + README 제출)
- 콘솔 출력
    - data.json 모드 수행 시 전체 테스트 수/통과 수/실패 수를 출력한다.
    - 실패 케이스가 있다면, 케이스 식별자와 실패 사유(요약)를 함께 출력한다.
- README 작성
    - “결과 리포트” 섹션에 실패 원인 분석 + 시간 복잡도 분석을 최소 10줄 이상 서술한다.
    - 실패가 0개인 경우에도, “왜 실패가 0이 되었는지(정규화/epsilon 정책)”를 요약한다.
4. 실행 흐름
- 프로그램 실행 시 아래 흐름이 순서대로 동작해야 한다.
    - 입력 방식 선택: 사용자 입력(3×3) 또는 data.json 분석
    - 사용자 입력 모드: 필터 A, B 입력 → 저장 확인 → 패턴 입력 → MAC 연산 → 결과 판정 → 성능 분석(3×3) 출력
    - data.json 분석 모드: 필터 로드 → 패턴 로드/검증 → MAC 연산/판정/PASS-FAIL 출력 → 성능 분석(3×3 포함, 5×5/13×13/25×25) 출력 → 결과 요약 출력


## 보너스 과제
### 1. 시뮬레이터 최적화(메모리 접근)
- 2차원 배열을 1차원 배열(길이 N²)로 변환해 접근 패턴을 단순화한다.
- 최적화 전/후 성능 분석(동일 입력, 동일 반복 횟수) 결과를 비교한다.
### 2. 패턴 생성기 개발
- 크기 N 입력 시, N×N 십자가(Cross)와 X 패턴을 자동 생성한다.
- 생성된 패턴을 모드 1/성능 분석에 재활용할 수 있게 구성한다.
